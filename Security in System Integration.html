2. Authentication vs. Authorization

Authentication

“Who are you?”

Password + MFA, passkey, certificate, identity provider, session/token.

Authorization

“What are you allowed to do?”

Role, permission, scope, ownership, business rules.

4. Authorization Models

RBAC

Permissions grouped into roles.

Example: Faculty can approve grades.

ABAC

Policy evaluates attributes.

Example: Faculty + assigned section can approve.

ACL

Permissions attached to resources.

Example: User A can read File X.

Ownership

Subject can act on owned resource.

Example: Student can edit own profile.

Default: deny unless a clear policy grants access.

6. JWT — Decode the Idea, Not the Secret

A JWT is a compact claims format. Signing provides integrity/authenticity; it does not automatically provide confidentiality.

HEADERalg · typ · kid
PAYLOADsub · iss · aud · exp · scope
SIGNATUREIntegrity / authenticity
Validate signature
Validate issuer / audience
Validate expiration
Apply scope / role policy
Critical: Base64url encoding is not encryption. Never store passwords or secrets in an ordinary JWT payload.

9. API Key vs JWT vs OAuth 2.0

API Key

Application/caller identification.

Simple service integration; watch leakage and lifetime.

JWT

Claims-bearing token.

Stateless API authorization; validation and theft matter.

OAuth 2.0

Delegated access.

User + third-party authorization; scope and configuration matter.

Architecture rule: No credential is secure by itself. Implementation and lifecycle management matter.

16. Security Testing — Attack the Happy Path

Authentication Tests

Expired, malformed, forged, missing, wrong-audience tokens.

Authorization Tests

Other-user objects, roles, tenants, privileged functions.

Input Tests

Unexpected types, sizes, nested structures, malicious strings.

Abuse Tests

High frequency, large pages, repeated business actions.

Integration Tests

Untrusted third-party responses, timeouts, dependency failures.

Configuration Tests

Debug endpoints, CORS, methods, old versions, defaults.

Security test: prove that unauthorized or unsafe behavior is rejected and observable.
